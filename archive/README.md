# Archived product lines

2.5, 2.6 and 2.7 live here. They are frozen: nothing in this directory builds, publishes, or is
read by CI. The live line is 2.8, under `epirhandbook/2.8/`. See the
[root README](../README.md).

| Line | What it was |
|---|---|
| [2.5](epirhandbook/2.5/README.md) | One monolithic image on the frozen R 4.3.2 stack, built from `renv.lock`. |
| [2.6](epirhandbook/2.6/README.md) | The same 4.3.2 stack split into `epirhandbook-common` plus 50 per-chapter images, all generated by `generate.py`. |
| [2.7](epirhandbook/2.7/README.md) | The forward port to the 2026 stack (R 4.6.0), still `epirhandbook-common` plus 49 per-chapter images. |

## Nothing here builds

CI loads exactly two catalogue files, `images.yaml` and `epirhandbook/2.8/images.yaml`. The
catalogues under this directory are not among them, so no workflow, test or script reads them.

## What survives on GHCR

The `appliedepi` organization holds exactly nine container packages, and their names are exactly
the nine names of the 2.8 catalogue. Verified on 2026-09-08 with the GitHub packages API. No
package carries the 2.5 monolith's name (`epirhandbook`), and none carries a per-chapter name of
2.6 or 2.7. Two names appear in both eras: `epirhandbook-common`, and `epirhandbook-basics`, which
was a per-chapter name then and is a group name now.

One pre-2.8 tag does survive. `epirhandbook-common:2.7` is a distinct digest inside the
`epirhandbook-common` package, dated 2026-07-24. Every other published tag is `2.8`, or
`4.6.0-2026-07-01` on `rbase`. Nothing builds or consumes the 2.7 tag.

## These files are frozen

Read them as a record of method, not as instructions. Their paths, links and commands describe the
repository as it was before 2.8, and the move into `archive/` did not repair any of them. Do not
run `epirhandbook/2.6/generate.py` or `epirhandbook/2.7/archive/generate.py`.
